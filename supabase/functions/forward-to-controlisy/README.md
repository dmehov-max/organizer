# forward-to-controlisy — препращане на качените документи към Controlisy

Добавено на 06.11.2026 (миграция `0079_controlisy_forwarding.sql`),
тест със Скрийн бокс ООД. На живо като **`forward-to-controlisy`**
(verify_jwt изключен, виж „Кой може да вика“).

## Идея

Клиентът качва документи през личния си линк (`upload.html`, 0059).
Органайзерът ги записва в `incoming_documents` и веднага ги праща по
имейл на папката на фирмата в Controlisy. Така:

- ние знаем кой какво е пратил и кога (без да зависим от API на
  Controlisy за четене);
- счетоводителите работят в Controlisy както досега;
- напомнянията за документи могат да спират сами.

## Адресите в Controlisy

В Controlisy всяка папка (Покупки / Продажби) има уникален адрес
„имейл към папка“ от вида `docs+<код>@controlisy.bg`. Намира се в
папката → *Специални разрешения за папката* → *Получаване по имейл* →
*Отвори*. **Трябва да е разрешено** („Не е разрешено“ = писмата се
губят).

Адресите се въвеждат в досието на клиента (поле „Controlisy“, Покупки
и Продажби). Само `@controlisy.bg` се приема, за да не тръгне документ
на клиент към грешен адрес при печатна грешка.

## Кой документ къде отива

| Адреси на фирмата | Къде |
|---|---|
| само един (Покупки или Продажби) | винаги там, клиентът не избира |
| и двата | клиентът избира „Покупки / Продажби“ при качване (`upload.html`); без избор не се праща, а чака „Прати“ от таблото |
| нито един | не се праща, колоната Controlisy показва „—“ |

Един файл = едно писмо, от `info@mehovconsult.com` през SMTP на
домейна (същите secrets като `vat-documents-reminder`: `SMTP_HOST`,
`SMTP_USER`, `SMTP_PASSWORD`). Тема: `<Фирма> — <Покупки|Продажби> —
<име на файла>`.

## Кой може да вика

- `upload-document` веднага след качване, с хедър
  `x-internal-secret` = `SUPABASE_SERVICE_ROLE_KEY`;
- таблото (бутон „Прати“ / „Прати пак“ в „Входящи документи“) с JWT на
  активен служител.

`verify_jwt` е изключен нарочно: включен, той пуска и публичния anon
ключ, т.е. не пази нищо. Проверката е в кода.

## Какво се записва

В `incoming_documents`: `kind` (purchase/sale), `forwarded_at`,
`forwarded_to`, `forward_error`. Грешка при препращане **не проваля
качването** — файлът е при нас, в таблото се вижда „грешка“ и „Прати
пак“.

## Лоши сценарии (покрити в `index.test.ts`)

- без адрес / два адреса без вид → не се праща, записва се причина;
- адрес извън `@controlisy.bg` (вкл. `controlisy.bg.evil.com`, няколко
  адреса през запетая) → отказ;
- документ „засечен по имейл“ (без файл при нас) → няма какво да се
  препрати;
- SMTP грешка → `forward_error`, „Прати пак“.

## Какво не прави

Не проверява дали Controlisy реално е приел писмото. Controlisy праща
грешка на подателя (info@) при неуспешно качване — ако тестът покаже,
че това се случва, следващата стъпка е четене на тези грешки по IMAP.
